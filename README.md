# SES Manager Pro (SES業務管理システム)

## 📌 プロジェクト概要 (Project Overview)
**SES Manager Pro**は、日本のSES（システムエンジニアリングサービス）企業向けに特化して開発された、モダンで直感的な統合業務管理システムです。

要員（エンジニア）のスキル・稼働状況の管理から、顧客・案件の管理、提案活動の進捗パイプライン（カンバン方式）、そして契約の予実管理や全社の売上・稼働率といった経営指標のダッシュボード可視化まで、SES営業およびバックオフィス業務に必要な一連のフローをフルスタックでサポートします。

本システムは、圧倒的な高級感と没入感を演出する「ダークモード×Glassmorphism（すりガラス効果）」を基調としたプレミアムUIを採用しており、日々の単調な管理業務を快適かつスタイリッシュな体験へと昇華させます。

## 🛠️ 技術スタック (Tech Stack)

### バックエンド (Backend)
- **Java 17+**
- **Spring Boot 3.3.x**: アプリケーションフレームワーク
- **Spring Security**: ログイン認証、ロール別メニューアクセス制御、パスワードのハッシュ化（本番BCrypt / 開発平文の環境別切替）
- **MyBatis-Plus**: O/Rマッパー（ページネーション、自動タイムスタンプ機能活用）
- **H2 Database / MySQL 8.0**: リレーショナルデータベース

### フロントエンド (Frontend)
- **HTML5 / CSS3 / Vanilla JavaScript**: ピュアで高速なフロントエンドロジック（jQuery/AJAXベース）
- **Thymeleaf**: サーバーサイドテンプレートエンジン（Layout Dialectによる共通フラグメント化）
- **Bootstrap 5**: レスポンシブUIコンポーネント基盤
- **Chart.js**: ダッシュボードの売上・ステータス分析グラフ描画
- **SortableJS**: 提案管理画面でのドラッグ＆ドロップ（カンバンUI）の実装
- **Bootstrap Icons (bi)**: 一貫性のあるアイコンシステム

## ✨ 主な機能 (Key Features)

1. **📊 経営分析ダッシュボード (Dashboard)**
   - 全社稼働率、Bench（待機）要員数、当月予想売上、粗利率などの重要KPIをリアルタイムに集計。
   - 契約終了が30日以内に迫っている「退場予定者アラートリスト」を自動生成し、営業機会の損失を防ぎます。
   - 売上推移や要員ステータス分布をリッチなグラフ（Chart.js）で視覚化。

2. **🧑‍💻 要員（エンジニア）管理 (Engineer Management)**
   - エンジニアの基本情報、スキルセット、希望単価、稼働状況（稼動中・Bench・提案中など）の一元管理。
   - 検索・絞り込み機能と、AIマッチングの拡張を見据えたUI基盤。

3. **🏢 顧客・案件管理 (Customer & Project Management)**
   - 顧客情報および、顧客が募集している案件の管理。
   - 単価幅、リモート区分、募集ステータスなどの要件定義をデータベースで正確にリレーション管理。

4. **🚀 提案パイプライン・カンバンUI (Proposal Kanban)**
   - 「書類選考中」「一次面接」「成約」「見送り」などの提案状況を、直感的な**ドラッグ＆ドロップ可能なカンバンボード**で管理。
   - 状態を変更した際は、非同期通信（AJAX）で瞬時にデータベースへ反映。

5. **📄 契約・アサイン管理 (Contract Management)**
   - 案件に対して要員をアサインし、売上単価・原価単価・期間などの契約情報を記録。
   - ダッシュボードのKPI算出の基盤となる重要データを管理。

6. **🤝 担当営業・営業成績／インセンティブ管理 (Sales Assignment & Commission)**
   - 要員に担当営業（複数可・主担当フラグ・担当履歴）を紐付け、待機要員のフォロー責任を明確化。要員一覧・待機リストに担当営業を表示し絞り込み可能。
   - 提案の成約時、契約に「成約担当営業」を自動設定（その時点の主担当を既定値とし変更可）。成績・インセンティブは契約単位で帰属するため、後日の担当変更が過去実績に影響しません。
   - 営業ごとに **担当要員数・成約件数・成約率・稼動中契約の売上／粗利・インセンティブ額** を月次で集計する営業成績画面。インセンティブ既定規則（基準＝粗利/売上・料率％）は管理者がシステム設定画面から変更でき、契約単位で個別に上書きも可能。

7. **👥 ユーザー・権限管理 (User & Permission Management)** — *管理者専用*
   - システム利用者のアカウントを画面から登録・編集・有効/無効化・削除でき、ロール（管理者 / 営業 / HR / マネージャー）を割り当て。
   - **ロール別メニュー権限**: ロールごとにアクセス可能な画面（サイドバーの各メニュー）と対応APIをチェックボックスで設定。許可されていない画面はサイドバーに表示されず、URL直打ちも遮断されます。
   - **安全設計**: ユーザー管理画面自体は管理者ロールのみアクセス可能。自分自身の削除・無効化・ロール変更（自己降格によるロックアウト）を防止し、管理者は権限設定によらず常に全画面にアクセス可能。
   - **パスワード**: 開発環境は平文、本番環境（`prod`プロファイル）ではBCryptハッシュ化に自動で切り替わります。

8. **📥 メール自動取込（案件 / 要員空き状況）(AI Email Ingestion)**
   - パートナーMLに届く案件メールを本文貼り付け・`.eml`アップロードから取り込み、AIが案件名・必要スキル・単価幅・勤務地・商流などを構造化。人が1画面レビューして確定すると案件（`t_project`）が起票され、そのままBench要員へのマッチ候補が提示されます。
   - 「この要員空いてます」メールも同じ仕組みで取り込み、**外部要員在庫**としてDB化。自社要員＋外部在庫を横断してマッチングできます。
   - 取込ジョブは `取込待ち→抽出中→要確認→確定済/却下/失敗` の状態機械で管理。抽出した原文（個人情報を含む）は保持期間経過後に自動でパージされます。

9. **🤖 AI提案文生成・マッチング (AI Proposal Draft & Matching)**
   - 要員×案件から、マッチ理由・セールスポイント・**提案メール下書き**をAIが生成し、カンバンからそのまま利用できます。ルールベースのスコア計算結果を根拠としてAIに渡すため、理由文が実データと乖離しません。
   - 個人情報保護のため、AIへ渡す氏名は**イニシャル**に置き換えています。
   - ※既定は `ai.provider: mock`（決定論的なモック応答）です。実際のAI接続は `application.yml` で `gemini` に切り替えて利用します。

10. **🛡️ 重複提案ガード・匿名スキルシート出力 (Duplicate Guard & Anonymized Skill Sheet)**
    - 同一要員を同一客先へ二重提案しようとした際に警告（ブロックはせず確認）。要員詳細には提案履歴（提案先・時期・結果）タブを追加。
    - 提案用スキルシートを**匿名化**（氏名をイニシャル化し連絡先等を伏字化）して出力可能。自社標準／簡易／客先様式から選べ、PDF・Excelの両形式に対応します。

11. **💰 資金繰り予測・入金消込 (Cash Flow Forecast & Payment Reconciliation)**
    - 入金予定（請求書の支払期日）と支払予定（BP支払・給与・固定費）を月次で突き合わせ、**ネットキャッシュと残高見込み**を可視化。残高が警戒ラインを割り込む月は日次バッチが管理者へ通知します。CSV出力にも対応。
    - freee連携で取得した銀行入金明細と請求書を金額・振込名義・時期で自動突合。**確実な一致のみ自動消込**し、曖昧なものは候補提示にとどめて人が確定します。

12. **📅 契約更新カレンダー・将来稼働率予測 (Renewal Calendar & Utilization Forecast)**
    - 全契約の更新期限をカレンダーで俯瞰し、未対応の契約は期限のN日前に担当営業→上長の順でエスカレーション通知。更新漏れによる失注を防ぎます。
    - 契約終了日と自動更新設定から1〜3ヶ月先の**稼働率・Bench発生を予測**し、ロールオフ予定要員を先出し。当月の値はダッシュボードKPIと必ず一致する共通ロジックで算出しています。

13. **⚖️ 労務コンプライアンス・要員フォロー (Compliance Check & Retention)**
    - 多重下請けの段数超過、偽装請負の兆候（準委任/請負なのに指揮命令の実態あり）、二重派遣、契約種別と精算実態の不整合を検査し、契約登録・更新時と月次締めチェックリストで警告。判定ルールと閾値は管理者が設定画面から調整できます。
    - 1on1・面談・連絡といったフォロー記録を要員ごとに蓄積し、長期Bench・低満足度・フォロー間隔超過から**定着リスクスコア**を算出。次回フォロー期日を過ぎた要員は担当営業へ通知されます。

## 🎨 UI/UXのこだわり (Design Aesthetics)
- **Glassmorphism**: モーダル、ドロップダウン、カードUIにすりガラスのような美しい透け感とブラー効果を取り入れ、モダンSaaSとしての圧倒的な質感を表現。
- **Fluid Animations**: モーダル起動時のバウンス効果（cubic-bezier）や、ホバー時のマイクロインタラクションによる「触って気持ちいい」操作感。
- **Dark Theme First**: 長時間の業務でも目が疲れにくい、洗練されたダークテーマをベースに構築。

## 🌍 国際化 (Internationalization / i18n)
本システムは多言語対応（日本語 / 英語 / 簡体字中国語 / 韓国語）を実装しています。UI上のヘッダーから言語を切り替えることで、Cookieに設定が保存され、画面の静的文言、Java層の例外メッセージ、JavaScriptの動的メッセージ、およびステータス等の列挙値ラベルが選択した言語で表示されます。

**現在の遺留事項（今後の検討課題）:**
- **メールテンプレート**: 自動生成されるメールの雛形（提案メールなど）は日本語のままとなります。
- **帳票出力（PDF）**: 請求書などのPDF出力は、中国語・韓国語フォントの埋め込み課題のため日本語固定としています。
- **CSVデータ列の列挙値**: 出力ファイルのヘッダー行は現在ロケールに追従しますが、データ列内の列挙値（「稼動中」など）は再取込やシステム間連携の突合一貫性を保つため、元のDB日本語値のまま出力されます。

## 🚀 起動方法 (How to Run)

本プロジェクトには Maven ディストリビューション (`apache-maven-3.9.6/`) が同梱されています（Mavenラッパー `mvnw` は含みません。システムに `mvn` が入っていればそちらでも構いません）。ローカル環境で起動する場合は以下の手順を実行してください。

1. **環境の準備**: Java 17以上がインストールされており、`JAVA_HOME` が正しく設定されていることを確認してください。

2. **データベースの準備 (MySQL)**:
   アプリ本体はMySQLに接続します（`application.yml` の `jdbc:mysql://localhost:3306/ses_manager_db`）。スキーマ・初期データは **Flyway** により起動時に自動適用されるため、手動でのSQL実行は不要です。**起動前に**以下を実施してください。DBが起動していないと、ログインやCRUDが「認証エラー」のように見える現象が起こるため注意してください。
   1. MySQLを起動する（未インストールの場合は導入、またはDockerで `mysql:8` を起動）。
   2. **空の**データベースを作成する: `CREATE DATABASE ses_manager_db;`
   3. アプリを起動すると、Flyway が `src/main/resources/db/migration/`（`V1`〜`V14`）を順に適用し、テーブル定義と初期管理者 `admin/admin123` を含むマスタデータを自動投入します。

   > 💡 `V1__create_tables.sql` は**統合ベーススキーマ**（後続の列追加を折り込み済み）です。列を追加する際は V1 の `CREATE TABLE` に追記し、後続マイグレーションで同じ列を再度 `ADD COLUMN` しないでください（空DBからの適用が「Duplicate column」で失敗します）。
   > 💡 既存の（旧 `sql/001`〜`008` を手動適用済みの）DBに対しては、`baseline-on-migrate: true` / `baseline-version: 9` により V1〜V9 は再実行されず V10 以降のみ適用されます。
   > 💡 既定の `mvn test` はH2/unit/MVCの高速feedback suiteで、`mysql`/`performance` tagを明示的に除外します。Dockerの有無で実行範囲が変化することはありません。
   > 💡 実MySQL/Flywayは `mvn test -Pmysql-tests`（Docker必須）、性能回帰は `mvn test -Pperformance-tests` で実行します。push前は `scripts/verify-like-ci.sh`（Windowsは `scripts\verify-like-ci.ps1`）を実行すると、CIと同じ3つのgateとbackup integrationを検証します。

3. **プロジェクトのビルドと起動**:
   プロジェクトのルートディレクトリで以下のコマンドを実行します。
   
   **Windows (PowerShell/CMD):**
   ```cmd
   .\apache-maven-3.9.6\bin\mvn spring-boot:run
   ```
   *(※システムに Maven が導入済みであれば `mvn spring-boot:run` でも起動できます)*

   > 💡 既存ローカルDBで `Migration checksum mismatch` が出た場合は、過去 migration の内容が更新されたあとに古い checksum が `flyway_schema_history` に残っている状態です。SQLファイルを戻せない前提なら、内容確認のうえで次を実行して checksum を再同期してください。
   >
   > **Windows (PowerShell/CMD):**
   > ```cmd
   > set DB_URL=jdbc:mysql://localhost:3306/ses_manager_db?useUnicode=true^&characterEncoding=utf-8^&serverTimezone=Asia/Tokyo
   > set DB_USERNAME=root
   > set DB_PASSWORD=123456
   > .\apache-maven-3.9.6\bin\mvn flyway:repair
   > ```
   >
   > その後に再度 `.\apache-maven-3.9.6\bin\mvn spring-boot:run` を実行してください。新規DBでは `repair` は不要です。

4. **アクセス**:
   アプリケーション起動後、ブラウザで以下にアクセスしてください。
   - URL: `http://localhost:8080/`
   - ログインページ: `http://localhost:8080/login`
   - 初期ログイン情報: `admin` / `admin123`（`db/migration/V2__init_master_data.sql` の初期データに準拠）
   - ログイン後、サイドバーの **「ユーザー管理」**（管理者のみ表示）から従業員アカウントを追加し、ロールごとのメニュー権限を設定できます。

   > 🔐 **本番運用時の注意**: 開発環境ではパスワードを平文で扱いますが、`prod` プロファイル（例: `--spring.profiles.active=prod`）で起動するとパスワードは自動的にBCryptでハッシュ化されます。本番ではアプリ経由でアカウントを作成し、平文の初期パスワードをそのまま残さないでください。
