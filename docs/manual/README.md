## 3. 手順書テーブルの標準列構成

各業務シート（01〜09）は、日本国内のエンタープライズシステム標準に準拠した以下の列構成で整理されています。

| 列名 | 項目説明 | 記載例 |
|:---|:---|:---|
| **項番** | 一意の識別番号 | `3-5` |
| **大項目** | 業務領域カテゴリ | `提案管理` |
| **中項目** | 機能名・画面名 | `提案カンバンボード操作` |
| **画面URL / パス** | システム内のアクセスパス | `/proposal/kanban` |
| **対象ロール** | 操作可能なロール権限 | `管理者 / 営業 / マネージャー` |
| **操作種別** | 操作の分類 | `ステータス更新 / CRUD / 照会 等` |
| **操作手順** | 1から始まる具体的な実行ステップ | `1. [提案管理] を開きます。\n2. カードをドラッグ＆ドロップします...` |
| **キャプチャID** | 紐付けるスクリーンショットのID | `CAP-SAL-005` |
| **画面内赤枠・番号対応** | キャプチャ画像内の赤枠・丸数字（①②③）との対照 | `① 提案ステータス列\n② 提案カード\n③ [新規提案]ボタン` |
| **主要入力項目・設定値** | 入力フォームの主要項目と設定例 | `提案単価（月額）、精算幅（140-180h）` |
| **確認事項・完了条件** | 成功時の画面状態（ゴール） | `カード移動時に非同期保存され、成約時は契約作成ボタンが出現` |
| **注意事項・制限事項** | 例外処理や業務上のTips | `成約レーンへ移動すると契約管理へ連携可能。過去月締め済みは編集不可` |

## 4. 画面キャプチャ撮影と画像の紐付けルール

手順書の各項目には、対応する画面キャプチャID（例：`CAP-SAL-005`）が採番されています。実際の画面キャプチャを撮影・保管する際は、以下のルールを遵守してください。

### 4.1 画像ファイル命名規則
`docs/manual/images/<カテゴリ>/<キャプチャID>_<機能名簡略>.png`
* 例：`docs/manual/images/sales/CAP-SAL-005_proposal_kanban.png`

### 4.2 キャプチャ加工ルール
1. **赤枠による強調**:
   * 操作対象のボタンや入力欄は、赤枠（角丸 2px、カラーコード `#D9383A` または `#E60012`）で囲みます。
2. **丸数字（ナンバリング ① ② ③）の付与**:
   * 操作順序に合わせて赤色の丸数字（①、②、③...）を配置し、Excel手順書内の「画面内赤枠・番号対応」の番号と完全一致させます。
3. **機密情報のマスキング**:
   * 個人名（実在する社員名）、実在の取引先名、銀行口座番号、APIキー等は必ずモザイクまたは黒塗りでマスキングし、標準サンプルデータ（例：`山田 太郎`、`株式会社テストシステム`）を使用してください。
4. **トリミング**:
   * 画面全体図（引き）で配置関係を示し、モーダルやプルダウン操作などの詳細操作は適宜拡大トリミング（寄り）で作成してください。
