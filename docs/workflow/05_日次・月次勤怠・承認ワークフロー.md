# 05. 日次・月次勤怠・承認ワークフロー詳細仕様書

## 1. プロセス概要
本フローは、エンジニアによる日次の自社雇用出退勤打刻、客先現場での実稼働工数（マイ勤怠）入力、休暇申請、月末の客先エビデンス（作業報告書PDF等）添付・勤怠提出、直属マネージャーによる承認受信トレイでの審査・承認・差戻し、およびHRによる全社36協定・過重労働モニタリングプロセスを定義します。

---

## 2. スイムレーン別アクティビティフロー図

```mermaid
sequenceDiagram
    autonumber
    actor E as 要員(自社/BPエンジニア)
    actor M as 直属マネージャー
    actor HR as HR/労務担当
    actor SYS as システム自動監視

    rect rgb(235, 245, 255)
        Note over E,SYS: 日次運用フェーズ
        E->>E: 出勤・退勤打刻（雇用勤怠） [/my/attendance]
        E->>E: 客先作業時間・作業概要入力 [/my/timesheet]
        opt 休暇取得時
            E->>M: 休暇申請（有休/半休/特別休暇） [/my/leave]
            M-->>E: 休暇承認・残日数自動更新
        end
        SYS->>HR: 36協定残業時間（45h/80h）超過警告自動検知
    end

    rect rgb(240, 255, 240)
        Note over E,M: 月末締め・提出・承認フェーズ
        E->>E: 当月全日入力完了確認
        E->>E: 客先勤務表エビデンス（PDF/Excel）添付
        E->>M: 「当月勤怠を提出」実行（編集ロック）
        M->>M: 承認受信トレイで工数・エビデンス突合確認 [/approval/inbox]
        
        alt 勤怠承認の場合
            M->>M: [一括承認] 実行
            M-->>E: 承認完了通知（ステータス「承認済」）
            M->>HR: 次工程「月次検収・請求計算」へ確定データ引き渡し
        else 記載不備・差戻しの場合
            M->>E: 差戻し理由コメント付きで [差戻し]
            E->>E: 理由確認・工数修正・再提出
        end
    end
```

## 3. 詳細業務アクティビティ一覧

| **5-5** | 月末エビデンス | 要員 | 営業 | クライアント企業から受領した公式勤務表・タイムシート（PDFやExcel等）を添付する。 | マイ勤怠入力 | 客先勤務表ファイル（PDF/Excel） | 添付エビデンスファイル | ファイル形式・ウイルススキャン検証 |

## 4. 例外処理・エスカレーション基準

1. **提出遅延要員への自動督促**:
   * 毎月第1営業日の12:00時点で未提出の要員に対し、システムが自動で「勤怠提出督促メール」を一斉送信します。
2. **客先工数と自社打刻の大幅乖離**:
   * 客先実稼働時間と自社雇用打刻時間の月間差異が一定時間（例: ±10時間）を超える場合、サービス残業または不正打刻防止のためHRによる個別ヒアリングが実施されます。
