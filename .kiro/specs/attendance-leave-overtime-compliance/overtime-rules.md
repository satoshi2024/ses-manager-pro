## 1. Tier A — 法令由来の値（変更は法改正または社労士指摘時のみ）

労働基準法36条（働き方改革関連法による上限規制）に対応する。
**「休日労働を含むか」がruleごとに違うのが最大の事故要因**なので、その列を必ず参照すること。

| # | ルール | 上限 | 境界 | 休日労働を含む | 対象期間 | config key |
|---|---|---|---|---|---|---|
| 1 | 月の時間外 | 45時間 | **45は適合**（超過が違反） | **含まない** | 暦月 | `overtime.limit.month-normal` |
| 2 | 年の時間外 | 360時間 | **360は適合** | **含まない** | 協定年度（12か月） | `overtime.limit.year-normal` |
| 3 | 年の時間外（特別条項） | 720時間 | **720は適合** | **含まない** | 協定年度（12か月） | `overtime.limit.year-special` |
| 4 | 月の合計 | 100時間 | **100は違反**（「100時間**未満**」） | **含む** | 暦月 | `overtime.limit.month-total` |
| 5 | 複数月平均 | 80時間 | **80は適合**（「80時間**以内**」） | **含む** | 2〜6か月のrolling | `overtime.limit.multi-month-average` |
| 6 | 45時間超の月数 | 年6回 | **6回は適合**（7回目が違反） | ルール1の定義に従う | 協定年度 | `overtime.limit.exceed-month-count` |

### 1.1 境界の実装形（off-by-one防止）

```
ルール1  violation := monthlyOvertimeMinutes >  45 * 60
ルール2  violation := yearOvertimeMinutes    > 360 * 60
ルール3  violation := yearOvertimeMinutes    > 720 * 60
ルール4  violation := monthlyTotalMinutes    >= 100 * 60   ← ここだけ >= 
ルール5  violation := avgTotalMinutes(n)     >  80 * 60   （n = 2,3,4,5,6 の全て）
ルール6  violation := exceedMonthCount       >   6
```

**ルール4だけが `>=`**。「未満」と「以内」の差である。ここを`>`で書くと100時間ちょうどを見逃す。
必ず`limit-1 / limit / limit+1`の3点fixtureで固定すること。

### 1.2 用語の定義

| 用語 | 定義 |
|---|---|
| 時間外労働 | 法定労働時間（1日8時間・週40時間）を超える労働。**法定休日労働は含まない** |
| 法定休日労働 | 法定休日（週1日）に行った労働 |
| 所定休日労働 | 法定休日以外の休日の労働。**時間外労働として扱う**（法定休日労働ではない） |
| 合計（ルール4/5） | 時間外労働 ＋ 法定休日労働 |
| 協定年度 | `m_overtime_agreement.valid_from` の月を起算とする12か月 |

**所定休日と法定休日の区別が必要**。週休2日で土日休みの場合、就業規則で法定休日を日曜と定めていれば、
土曜の労働は「時間外労働」、日曜の労働は「法定休日労働」になり、ルール1/2/3への算入可否が変わる。
法定休日の曜日は `m_work_calendar_day.type` で表現し、カレンダー側で持つ。

### 1.3 rolling平均（ルール5）の計算

- 対象月を**含む**直近n月の平均。`n = 2, 3, 4, 5, 6` の**すべて**を判定し、1つでも超過なら違反。
- **協定年度の境界をまたいで計算する。** ルール5は協定年度に紐づかない。
  年度またぎでリセットすると直近6か月の実態を見逃す。
- 対象月より前のデータが n か月分そろわない場合（入社直後・システム導入直後）は
  **そのnの判定をスキップ**する。不足月を0時間として平均を下げない。

## 2. Tier B — 運用パラメータ（自由に変更してよい）

法令ではなく運用判断で決めた値。変更に社労士確認は不要。

| # | 論点 | 決定 | 根拠 | config key |
|---|---|---|---|---|
| 7 | 協定の起算日 | **月初（1日）に限定する** | 月中起算を許すと「月」の定義が全計算へ波及する。月初制約なら暦月＝協定月で一致する。`valid_from`が月初でない`m_overtime_agreement`は登録時に拒否 | （制約。configなし） |
| 8 | 月中入社・退職 | **按分しない。実績のみで判定** | 上限が月単位で定義されるため。按分すると法定の月上限より厳しい判定になる | `overtime.prorate-partial-month`（既定 `false`） |
| 9 | 協定の期間途中変更 | **変更日で期間を分割し、それぞれの協定で判定** | 通算すると旧協定の特別条項有無が新期間へ漏れる | （構造。configなし） |
| 10 | 予兆警告の閾値 | 各上限の **80%** | 超過してからでは遅い。月45hなら36h時点で本人へ通知 | `overtime.warning.threshold-percent` |
| 11 | 段階通知 | 予兆=本人 / 超過=本人＋上長 / 複数月平均超過=本人＋上長＋HR | R3.3の段階通知 | `overtime.warning.recipients`（`self,manager,hr`） |
| 12 | 丸め | **丸めなし。分単位で保持し表示時に時間換算** | 丸めると境界judgmentがずれる。`design.md`§1の分整数モデル | （構造。configなし） |
| 13 | 日をまたぐ勤務 | **始業日の勤務として1日に計上** | JST日界。労基法の「1日」は始業時刻の属する日 | （構造。configなし） |
| 14 | 適用除外 | 管理監督者・適用除外者は**ルール1〜6の対象外**。深夜割増のみ適用 | 労基法41条2号。R3.2の「個人適用区分」 | `t_employee_attendance`ではなく要員側の区分フラグ |

## 3. 法人別の上書きと優先順位

値の解決は**上から順に、最初に見つかったものを採用**する。

```
1. m_overtime_agreement の該当法人・該当期間の行（limits/config列）   ← 法人別の実協定
2. m_system_config の overtime.* キー                                  ← システム既定
3. コード内の定数（本書 Tier A の値）                                   ← 最終fallback
```

- **1が本命。** 法人ごとに36協定の内容（特別条項の有無、上限値）が違うのが実態なので、
  `m_overtime_agreement`に実際の協定内容を登録すれば法人別に正しく判定される。
- 2は「まだ協定を登録していない法人」の暫定既定。
- 3はDBが空でも計算が壊れないための保険であり、**運用でここに依存しない**。
- `m_overtime_agreement`が存在しない法人は、**判定不能としてfindingを出す**。
  既定値で「適合」と判定しない（fail-closed）。

`special_clause = false` の協定では、ルール3（年720h）・ルール4・ルール5・ルール6を**判定しない**。
特別条項がなければ月45h・年360hを超えられないため、超えた時点でルール1/2の違反になる。

## 4. 値を変更する手順

### 4.1 いちばん速い変更（閾値だけ変える）

社労士確認の結果、値がずれていた場合はこれで済む。**デプロイ不要・コード変更不要**。

1. 管理者で `/system-config` を開く。
2. 対象の `overtime.*` キーの値を変更して保存。
3. 本書 §1 または §2 の該当行の値を同じ値へ更新し、変更日と理由を §6 へ追記する。
4. 次回の月次判定から新しい値が使われる。**過去の判定結果は再計算しない**
   （確定済みの月次は`platform-invariants.md`§1のsnapshot規約に従い不変）。

### 4.2 法人別に変える

1. `/attendance` の36協定管理から、該当法人の `m_overtime_agreement` を登録・更新する。
2. `valid_from` は**月初**にする（§2 #7の制約）。
3. 期間途中の変更は、旧行の`valid_to`を前月末で閉じ、新行を作る。既存行を書き換えない。

### 4.3 境界の包含/排他を変える（法改正時）

これだけはコード変更を伴う。§1.1の6行の比較演算子が実装上の唯一の箇所になるよう、
`OvertimeComplianceCalculator`に**判定式を1メソッド1ルールで**書くこと。
条件が複数箇所に散っていると、この変更が漏れる。

1. `OvertimeComplianceCalculator` の該当ルールの比較演算子を変更。
2. 対応する境界fixture（`limit-1/limit/limit+1`）の期待値を更新。
3. 本書 §1.1 を更新し、§6 へ追記。
4. L2（定向 + 直接回帰）を実行。M taskでL4。

### 4.4 「休日労働を含むか」を変える（法改正時）

§1の表の該当行と、`OvertimeComplianceCalculator`が使う入力（`overtimeMinutes` か `totalMinutes` か）を
変更する。**この2箇所以外に散らさない**こと。

## 5. テストfixtureの置き方

- 境界fixtureは `src/test/resources/fixtures/overtime/` にJSONで置く（`design.md` §2）。
- fixtureは**本書 §1 の値をハードコードせず**、config値を読んで `limit-1 / limit / limit+1` を生成する。
  こうしておくと §4.1 で値を変えてもfixtureが自動で追随する。
- ただしルール4の `>=` とルール5の `>` のような**境界の向きはfixtureに明示的に書く**。
  ここは値ではなく仕様なので、自動追随させると変更を検知できない。
- 公式の計算例が入手できたものは、出典URLと確認日をfixtureのコメントへ記録する。

推奨fixture最小セット（各ルール）:

| fixture | 期待 |
|---|---|
| `limit - 1分` | 適合 |
| `limit ちょうど` | ルール4のみ違反、他は適合 |
| `limit + 1分` | 違反 |
| 休日労働のみ`limit`超 | ルール1/2/3は適合、ルール4/5は違反 |
| 所定休日労働 | ルール1へ算入される |
| n月分のデータ不足 | そのnの判定をskip（0扱いにしない） |
| 協定年度またぎ | ルール2/3/6はリセット、ルール5はまたいで計算 |
| 適用除外者 | ルール1〜6すべて判定しない |
