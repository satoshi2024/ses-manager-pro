# NF-04 実機ブラウザ受入テンプレート（A-NF04-2）

- 状態: **人工受入テンプレート（未実施）**。自動テスト（Chrome / CDP）で再現できないブラウザ固有の挙動を、業務受入者が実機で確認するための手順と記録様式である。本テンプレートの存在は受入の完了・production 許可を意味しない。
- 対象ブラウザ（B-NF04-1）: iOS Safari、Android Chrome、Microsoft Edge（Windows / macOS）。可能なら macOS Safari も同じ項目で確認する。各ブラウザとも現行版と1つ前の版。
- 前提: `first-release-user-and-operations-notes.md`（利用者説明 1章、運用説明 2.4）、2026-11-14 の決定（NF04 P1-N4-1 = 方案A）。
- 記録先: 本specの `review-ledger.md`（下の記録様式を転記する）。画面キャプチャ等の証跡は個人情報を写さない環境（試験用の要員アカウント・試験データ）で取得する。

## 1. 準備

| 項目 | 内容 |
|---|---|
| 環境 | staging（本番と同じ OIDC 必須構成。`oidc.local-login-enabled=false`）。ローカルパスワードsessionの確認だけは、local login を有効にした検証環境で行う |
| アカウント | 試験用の要員アカウント（OIDC で login できるもの）。ローカルパスワードsessionの確認用に、local login 可能な検証環境の要員アカウント |
| 端末設定 | 端末の時計は自動設定。プライベートブラウズは使わない（使う場合は別行で記録する） |
| 通信の切替 | 機内モード、または端末のWi-Fi・モバイル通信をOFFにする |
| 機能スイッチ | NF-04（PWA shell）は OFF（初回リリースの既定）で確認する。ON の確認を行う場合は別行で記録する |

## 2. 確認項目

各項目の「期待結果」をすべて満たした場合だけ「合格」とする。満たさない場合は、端末・ブラウザ・版・手順・画面の状態を記録して「不合格」とする。

| ID | 対象session | 手順 | 期待結果 |
|---|---|---|---|
| S-01 | OIDC | 勤怠の日次入力画面を開き、通信を切って1件保存する | 同期パネルに「オフライン: 未送信 1 件。…離れると復元できません」と表示される |
| S-02 | OIDC | S-01 の状態で、画面内を一度タップしてから、別の画面へ移動しようとする（戻る操作・リンク・再読み込み） | ブラウザの離脱確認が表示される。「このページに留まる」を選ぶと入力が残る（ブラウザが確認を出さない場合は、その事実と手順を記録する） |
| S-03 | OIDC | S-01 の状態で通信を戻す | 自動で1回だけ送信され、サーバー側で1件だけ登録される。以後の画面移動では離脱確認が出ない |
| S-04 | OIDC | 通信を切って1件保存し、S-02 の確認で「離れる」を選ぶ（または再読み込み）。通信を戻して勤怠画面を開く | 同期パネルに「ロック中の下書き 1 件は、現在のログイン方式（シングルサインオン）では復元できません。…」と表示され、「下書きを復元」は表示されない |
| S-05 | OIDC | S-04 の状態で `/offline.html`（復元画面）を開く | パスワード欄・再認証ボタンが表示されず、「この下書きは復元できません。…」と表示される。アカウントがロックされない（その後も通常どおり操作できる） |
| S-06 | OIDC | S-04 の状態でログアウトを選ぶ | 「この端末に未送信またはロック中の下書きが N 件あります。…ログアウトしますか？」と確認が表示される。キャンセルではログアウトせず下書きも残る。確定するとログアウトし、再ログイン後に下書きは表示されない |
| S-07 | OIDC（Safari / iOS Safari のみ） | 通信を切って1件保存したまま、端末の日付を進めずに **7日間以上** 本システムを開かずに置く（Safari自体は他のサイトで通常どおり使う）。その後に本システムを開く | 記録項目: 下書きが「ロック中」として数えられるか、表示されなくなったか。**無効になる場合があることは既知の制限**（運用説明 2.4）であり、結果を記録して判定は Owner に委ねる |
| S-08 | OIDC（Safari / iOS Safari のみ） | 2〜6日ごとに本システムを開き続けながら、未送信の下書きを保存から8日以上置く | 撤回epoch cookie の期限延長により、下書きが「ロック中」として残る（S-07 との差を記録する） |
| S-09 | ローカルパスワード | 通信を切って1件保存し、再読み込みする。通信を戻して同期パネルの「下書きを復元」→ パスワード入力 → 「下書きを復元する」 | 「下書きを復元」が表示され、パスワードの本人確認後に内容が表示され、1回だけ送信される。離脱確認は表示されない |
| S-10 | ローカルパスワード | 復元画面で誤ったパスワードを入力する | 「再認証できませんでした」と表示される（既存の5回失敗/30分ロックが適用されることを確認する場合は、試験用アカウントで行う） |
| S-11 | 共通 | 保存後に端末の画面を切り替える（アプリ切替・タブ切替）し、通信のある状態で戻る | 送信済み、または同期パネルに未送信として残る。二重に登録されない |
| S-12 | 共通 | ログアウト後に同じ端末で別の要員がログインする | 前の要員の下書きは表示・送信されない |
| S-13 | 共通（390px相当のスマートフォン） | 同期パネル・復元画面を縦向きで表示する | 文言が切れずに読め、ボタンが指で押せる（44px以上） |

## 4. 判定の扱い

- S-01〜S-06、S-09〜S-13 の不合格は、production 前に修正または Owner の受入判断が必要である。
- S-07 は既知の制限の実測であり、結果にかかわらず「記録のみ」とする。S-08 が不合格（7日以内に再訪しても下書きが無効になる）の場合は、撤回epoch cookie の延長が効いていないため不具合として扱う。
- 離脱確認（S-02）がブラウザの仕様で表示されない場合は、利用者説明 1.4 の注意書きで足りるかを業務Ownerが判断する。
